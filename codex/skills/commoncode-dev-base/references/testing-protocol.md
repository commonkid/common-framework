# Протокол тестирования

Цель — 100% покрытие бизнес-логики при нулевом использовании браузера и запущенных серверов.
Тест обязан не только проверять результат, но и **производить семантический контекст**:
печатать траекторию LDD, по которой QA восстановит ход исполнения.

## Два обязательных теста

### 1. Backend & LDD Test

Проверяет сквозной путь: сохранение конфига → расчёт → запись в БД → чтение обратно.

- Все пути (конфиг, SQLite) переопределяются на `tmp_path` — тест не трогает рабочие файлы.
- `caplog.set_level(logging.INFO)` в начале.
- Печать записей `[IMP:7-10]` в консоль **до** финальных ассертов — чтобы след остался
  даже при падении.
- Финальный ассерт на присутствие `[IMP:9]` AI Belief State.
- Содержательная проверка инвариантов, а не только типов: при `a=2, c=3, x∈[-1,1]` в БД
  должны лежать ровно `[(-1,5), (0,3), (1,5)]`; колонка `x` монотонно возрастает.

Шаблон: `assets/templates/test_backend_ldd.template.py`.

### 2. UI Headless Test

Обработчики вызываются напрямую как обычные функции. Gradio-сервер не поднимается,
браузер не участвует.

- Проверяются типы возврата: `pd.DataFrame` с ожидаемым числом строк,
  `plotly.graph_objects.Figure` с ожидаемым числом трасс.
- Проверяются побочные эффекты: `config.json` действительно обновился.
- Проверяется деградация: инвертированный диапазон (`x_min > x_max`) возвращает
  `(DataFrame, str)` с сообщением об ошибке, а не исключение.
- Пути подменяются через атрибуты модуля: `ui.DB_PATH = tmp_path`,
  `ui._config_mgr.config_dir = tmp_path`.

Шаблон: `assets/templates/test_ui_headless.template.py`.

## Anti-Loop Protocol

`tests/conftest.py` ведёт счётчик неудачных прогонов в `.test_counter.json` рядом с модулем.
Счётчик переживает перезапуски — именно поэтому он на диске, а не в памяти: зацикливание
агента проявляется между запусками pytest, а не внутри одного.

Session-хуки:

- `pytest_sessionstart` — печатает `ANTI_LOOP_STATUS` и чек-лист типовых ошибок,
  если предыдущие прогоны падали.
- `pytest_sessionfinish` — при `exitstatus == 0` сбрасывает счётчик в 0, иначе инкрементит.

Эскалация:

| Провалов | Реакция |
|---|---|
| 3 | Искать решение вовне — MCP `tavily`, `Context 7` |
| 4 | `WARNING: Looping risk!` — остановиться и оценить, не повторяется ли проваленная стратегия (суперпозиция: рассмотреть альтернативу) |
| 5+ | `CRITICAL ERROR: Agent looping detected. STOP.` — сформулировать запрос оператору |

Чек-лист по умолчанию проверяет ровно те грабли, на которые агенты наступают чаще всего:
импорты через пакетные пути вместо `sys.path.append`, использование `tmp_path`, печать
`[IMP:7-10]` до ассертов, отсутствие запуска Gradio-сервера в UI-тестах.

Шаблон: `assets/templates/conftest.template.py`.

## Диагностика падений (Diagnostic Trio)

Фаза QA при провале анализирует три источника в связке — **Logs / Code / Data**. Лог даёт
фактическую траекторию, код — ожидаемую, данные — состояние, в котором они разошлись.
Вывод оформляется структурированным Bug Report, а не свободным текстом.

## test_guide.md

Для передачи в фазу QA пишется `test_guide.md`: входные данные (пути к конфигу, БД, логу),
список тестовых файлов, чек-лист проверок с ожидаемыми `[IMP:9-10]` маркерами, SQL для
независимой сверки и команда запуска.

Пример: `assets/templates/test_guide.example.md`.

## Запуск

```bash
python -m pytest tests/test_lesson_X.py -s -v
```

Флаг `-s` обязателен — без него печать LDD-траектории подавляется и тест теряет половину
своей ценности.

## Тесты безопасности

Если модуль работает с внешним API — отдельный тест проверяет, что `config.json` не содержит
поля с ключом. HTTP мокается через `unittest.mock.patch` на уровне клиента
(`openai.OpenAI.chat.completions.create`); реальные сетевые запросы в тестах запрещены.
