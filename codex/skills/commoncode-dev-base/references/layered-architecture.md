# Изоляция слоёв

Один модуль — одна ответственность и один способ ею пользоваться. Разрез проверен на
12 итерациях одной и той же задачи и держится независимо от стека (Gradio, CLI, tools-режим).

## Слои

| Слой | Модуль | Отвечает | Не знает про |
|---|---|---|---|
| Конфигурация | `config_manager.py` | Атомарное чтение/запись `config.json`, значения по умолчанию | БД, UI, расчёты |
| Расчёт | `engine.py` / `logic.py` / `parabola_engine.py` | Чистая бизнес-логика, возвращает данные | Файлы, SQL, UI |
| Хранилище | `db_manager.py` / `db_service.py` | Схема таблиц, запись и чтение | Откуда взялись данные |
| Обработчики | `handlers.py` / `ui_handlers.py` | Склейка слоёв под событие интерфейса | Виджеты, вёрстку |
| Интерфейс | `ui.py` / `ui_app.py` | Только описание компонентов и привязка к обработчикам | SQL, вычисления |
| Точка входа | `run_lesson_X.py` | Запуск | Всё остальное |

Правило, из которого следует остальное: **обработчик — единственное место, где слои
встречаются**. Движок расчёта не пишет в БД, UI не читает конфиг напрямую, менеджер БД
не считает точки.

Именно этот разрез делает возможным headless-тестирование: обработчик вызывается как
обычная функция, потому что не содержит ничего от Gradio.

## Управление состоянием

Единый `config.json` внутри папки модуля — единственный источник параметров. Работа с ним
вынесена в отдельный модуль целиком, включая дефолты при отсутствующем файле. Тест
round-trip обязателен: `save(a=3, c=-2)` → `load()` даёт `a == 3.0`; отсутствующий файл
даёт документированные умолчания.

## Инкапсуляция вместо venv

Новые виртуальные окружения не создаются, установленные библиотеки не переустанавливаются.
Изоляция достигается тем, что все файлы модуля — код, конфиг, БД, лог, счётчик тестов —
лежат внутри его папки:

```
lesson_X/
├── config.json          состояние
├── app_X.log            лог LDD
├── parabola_X.sqlite3   БД
├── .test_counter.json   счётчик Anti-Loop
├── AppGraph.xml         локальный граф (создаётся после зелёных тестов)
├── *.py                 модули по слоям
└── tests/
    ├── conftest.py      session-хуки Anti-Loop
    ├── test_backend_ldd.py
    └── test_ui_headless.py
```

Единственное зафиксированное исключение из запрета на установку — `openai>=1.0.0`,
если библиотеки нет в системе.

## Плагинная архитектура (Tool = Plugin)

Расширяемый вариант того же принципа: каждый инструмент — отдельный файл в `tools/plugins/`,
экспортирующий `TOOL_SCHEMA` (JSON-схема в формате OpenAI Function Calling) и `run(**kwargs)`.
Приложение сканирует папку на старте и собирает список инструментов динамически.

Диспетчер (`tool_executor`) передаётся в плагин через замыкание или декоратор, **не** через
сигнатуру `run()` — иначе схема инструмента протечёт в реализацию. Файл плагина именуется
по имени инструмента из его же схемы.

Подробное ТЗ: `assets/task-briefs/openai-tools-plugins.md`.

## Agentic UX

Интерфейс проектируется так, чтобы каждое действие пользователя было воспроизводимо
вызовом функции и оставляло след в логе. Практическое следствие: кнопка не содержит логики,
она вызывает обработчик; обработчик возвращает данные, а не рисует; всё, что произошло,
попадает в LDD-лог с маркером важности.
